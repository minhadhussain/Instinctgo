# InstinctGo backend

Python 3.11+, FastAPI, Pydantic, SQLAlchemy, Alembic, LangGraph, and ARQ.

## Run locally

From the repository root:

```powershell
uv sync --project backend
Copy-Item backend/.env.example backend/.env
npm run db:migrate
npm run dev:backend
```

Copy the environment file only on first setup. The initial setup already creates it.
The API runs at http://localhost:8000; interactive documentation is at `/docs`.
SQLite is the zero-service development default. Its path is always relative to `backend/`.

## Layout

| Folder | Responsibility |
| --- | --- |
| `app/api/v1/endpoints/` | HTTP routes and error mapping |
| `app/core/` | Environment configuration and structured logging |
| `app/schemas/` | API contracts and workflow dependency validation |
| `app/services/` | Business rules and database transactions |
| `app/repositories/` | Persistence queries |
| `app/models/`, `app/db/` | SQLAlchemy entities, metadata, and sessions |
| `app/agents/` | LangGraph state, orchestration, and prompts |
| `app/tools/` | Extension point for agent-callable business actions |
| `app/ingestion/parsers/` | TXT, Markdown, PDF, and DOCX text extraction |
| `app/integrations/` | Extension point for external-system adapters |
| `app/workers/` | Redis-backed asynchronous workflow drafting |
| `migrations/` | Versioned database schema changes |
| `storage/uploads/` | Local upload storage reserved for ingestion features |
| `tests/unit/`, `tests/integration/` | Test locations |

## Starter API

- `GET /api/v1/health` — process liveness.
- `GET /api/v1/health/ready` — database connectivity.
- `POST /api/v1/workflows/draft` — AI-generated workflow plan; requires `OPENAI_API_KEY`.
- `POST /api/v1/workflows` — validate and persist a draft.
- `GET /api/v1/workflows?limit=20&offset=0` — list saved drafts.
- `GET /api/v1/workflows/{id}` — fetch a saved draft.

Draft request:

```json
{
  "process_description": "Our team receives supplier invoices by email, extracts the invoice details, asks finance to review them, and records approved invoices in our ERP."
}
```

The draft response can be submitted directly to `POST /api/v1/workflows` to save it.
Steps have a unique `key`, `title`, `description`, `kind` (`human`, `agent`, or `integration`),
and `depends_on`. Dependencies must reference earlier steps in the plan.

AI credentials are loaded server-side from `backend/.env`. The default model is
`gpt-4.1-mini`; change `OPENAI_MODEL` to a model available to your account.

## PostgreSQL and Redis

SQLite handles local development. To use an existing PostgreSQL instance, set your
connection URL in `backend/.env`:

```dotenv
DATABASE_URL=postgresql+asyncpg://username:password@localhost:5432/instinctgo
```

Then run `npm run db:migrate` again for the new database. PostgreSQL and SQLite
are separate databases; switching the URL does not move existing drafts.

Workers need an accessible Redis service configured through `REDIS_URL`.
Once connected, start a worker with `npm run worker`.
An application service can enqueue a background draft like this:

```python
from uuid import uuid4

from arq import create_pool
from arq.connections import RedisSettings

from app.core.config import get_settings


async def enqueue_draft(description: str):
    redis = await create_pool(RedisSettings.from_dsn(get_settings().redis_url))
    try:
        job = await redis.enqueue_job("draft_and_save_workflow", description, _job_id=str(uuid4()))
        return job.job_id
    finally:
        await redis.aclose()
```

## Development commands

Run these from `backend/`:

```powershell
uv run ruff check .
uv run ruff format --check .
uv run alembic revision --autogenerate -m "describe schema change"
uv run alembic upgrade head
uv run alembic check
```

Review autogenerated migrations before applying them. `uv.lock` records exact Python versions.
Add tests as features develop; pytest, pytest-asyncio, and HTTPX are installed.

## Implementation status

This is a local development foundation. Workflow planning and draft persistence are wired up.
Document extraction is a callable helper; tools and integrations are extension points.
Execution, file-upload endpoints, OCR, authentication, and tenant-level access controls are
future features. The development server binds to loopback.
